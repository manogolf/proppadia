# NHL raw skater foundation integrity

Status: **historical foundation modified after the retained pre-live snapshot; original source provenance and the exact later writer invocations are incomplete.** This investigation is read-only. The broader Points foundation investigation remains open.

## Scope and evidence

This review follows the operator clarification that the NHL historical foundation built from 2023–2025 work was considered pristine before 2025 regular-season live collection. It tests that premise against the earliest retained database snapshot, Git history, current raw rows, retained official PBP samples, and the available writer code. It does not infer a row's source from a non-NULL value or claim that a writer ran merely because it exists in Git.

The earliest retained whole-table state is `backups/nhl_schema_and_data.sql`, committed as `58deab80` on 2025-10-10. Its SHA256 is `87cb47909de97ec3717e087acff344cf9514d5a01c6c42e812c5294a78010ee5`. Its `skater_game_logs_raw` COPY contains 100,386 rows across 2,790 game IDs, with `created_at` from 2025-09-20 through 2025-10-05. It includes 2023–24 and 2024–25 regular-season history and 145 rows from game-ID prefix 202501, but predates the 2025-10-07 regular-season start. The DDL has primary key `(player_id, game_id)`, nullable source measurements, and `created_at`; it has no `updated_at`, source endpoint, source response hash, validation status, or write-audit history. The snapshot is useful evidence of pre-live table state, not proof that each stored value was official or correct.

A read-only export of current rows with `game_id < 2025020000` is retained at `artifacts/analysis/nhl/raw_foundation_integrity_2026-10-16/current_raw_snapshot.csv`, SHA256 `fadf53ffaaefe518affe06b58f6ba7dd709dd070a3d025d1f3dc0fa2115fcc68`. The export contains 99,987 rows. On the 99,987 keys shared with the Oct. 10 dump, the following values differ:

| Field | Shared keys with changed value | Detail |
| --- | ---: | --- |
| `shot_attempts` | 88,199 | 50,710 changed values; 29,675 NULL-to-value changes; 7,814 NULL-to-zero changes |
| `shots_on_goal` | 25,680 | 25,615 NULL-to-zero changes; 65 NULL-to-value changes |
| `pp_toi_minutes` | 98,292 | changed; a field-level source audit is still needed to distinguish updates from corrections |

The other compared columns—including TOI, team/opponent identity, blocks, and the remaining shared source columns—match on these keys. There are 399 Oct. 10 keys absent from the current table and no current-only keys in this comparison. The 399 removals comprise 145 `202501` rows and 254 earlier-season rows; the archived `reset_2025.sql` can delete 2025 rows, but no execution evidence ties it to the 145 removals. The other deletions are unexplained. Because the raw table has no update audit, the value diffs establish post-snapshot modification, not which process made each change or whether the new value is correct.

The raw 2025/26 recovery database snapshot is `artifacts/analysis/nhl/points_attempts_2025_full_recovery_2026-10-16/database_snapshot.csv`, SHA256 `a2e7b6282edfec1b8272808495931270cca331e60181245f487eb1c6f77e6011`. It captures 46,713 current regular-season rows across 1,306 games, dated 2025-10-07 to 2026-04-15. This snapshot and the official-PBP recovery remain read-only; no SQL repair was run.

## What changed and when

1. `0ca753cb` (2025-09-27) adds the first retained `ingest_boxscore.py` version. It directly inserts/upserts raw player-game rows, and its PBP parser recognizes SOG, missed-shot, and blocked-shot event labels. The implementation lacks the later strict final-game, canonical shooter/team, event-uniqueness, and official player-SOG reconciliation gates. Its existence alone does not prove it populated the original foundation.
2. `1fd5f7c8` (2025-10-06) revises that ingest path. The committed `aggregate_attempts_from_pbp` docstring explicitly says only SOG/goal events are counted and missed/blocked attempts are left at zero. The direct raw UPSERT assigns `shot_attempts = EXCLUDED.shot_attempts` and can overwrite an existing value. It also assigns team/opponent/home/date, SOG, TOI, PP TOI, and SOG splits. It accepts an explicit game ID, so its code is capable of targeting historical games. No retained invocation receipt establishes that it wrote the current discrepant rows. The Oct. 10 dump's latest `created_at` is Oct. 5, before this commit; therefore this Oct. 6 revision cannot explain the baseline rows' initial creation.
3. `7b978031` (2025-10-12) adds the scheduled-date skater staging importer and a date-range backfill shell wrapper. Its `shotAttempts` fallback is `SOG + missedShots + blockedShots`, with missing operands defaulted to zero. The importer writes staging, not raw. The wrapper accepts historical date ranges, so values for Oct. 7 games could be produced later.
4. `8f15b81a` (2025-10-23) changes the importer to the top-level boxscore schema but retains that same three-term fallback. This is after the Oct. 7 game dates in question; game date is not acquisition or write date.
5. `b8cef981` (2025-10-28) introduces `backend/nhl/cli.py` and the staging-to-raw upsert. The regular daily path promotes the prior date, but `HONOR_ENV_DATES=1` allows an explicitly selected historical date. Promotion directly replaces team/opponent/home/date, SOG, and TOI; it uses `COALESCE` for attempts and treats incoming PP-TOI zero as NULL before preserving the old value. A bad staged attempt can therefore reach raw, and a missing later attempt will not clear it.
6. `fdeaf771` (2026-09-19) adds postgame stage-to-raw reconciliation. Its `_promote_stage` UPSERT can update identity, SOG, attempts (COALESCE), TOI, PP TOI, blocks and other source/stat fields for the selected historical slate. Current code is gated by explicit slate and reconciliation controls; no execution evidence attributes the older differences to it.

Other raw-table writers found in the bounded repository search include: `fill_pp_toi_minutes_for_date.py` (added 2026-01-13; updates raw PP TOI where it is NULL or zero), archived shift-chart/PBP/boxscore PP-TOI backfills (PP TOI only), `backfill_skater_blocks_from_boxscore.py` (blocks only), and the Oct. 27 points migration (adds/derives goals, assists, points). Archived points CSV loaders write goal/assist/point fields. The archived `reset_2025.sql` deletes 2025-season raw rows. The 2026 official-PBP repair SQL changes only attempts for validated 2026 keys. The 2025 modeling/scoring scripts examined read raw or exported histories; no direct raw-table write by model fitting was found. This separates downstream feature corruption from the actual operational/backfill paths capable of modifying source rows.

The source-selection change visible in Git is that the Sept. 27/Oct. 6 legacy writer fetched PBP and wrote its event-derived count directly to raw, while the Oct. 12 scheduled importer switched to Gamecenter boxscore `shotAttempts` with a three-field fallback and staged the result. That importer did not request PBP. Thus official PBP was available in an earlier code path, but the Oct. 12 daily source path did not use it to reconcile attempts. No retained design record explains why the new path selected a boxscore field not consistently present, and the later fallback's `blockedShots` field was not a shooter-bound blocked-attempt count. The Oct. 28 promotion then connected staging to raw. This establishes a code-path change, not proof that a particular Oct. 12 or Oct. 28 job wrote a given row.

## Pre-October-23 records with the fallback signature

In the six-game official-PBP sample retained at `artifacts/analysis/nhl/points_attempts_2025_integrity/sample_2026-10-16/`, 70 of 89 discrepant attempts values equal `SOG + missedShots + blockedShots` from retained Gamecenter boxscores. Twenty-three of those signature rows are all from game `2025020001`, dated 2025-10-07—before the Oct. 23 parser commit. Their database `created_at` is 2025-12-14 22:43:12 UTC. This proves those rows were first inserted after both the Oct. 12 importer and Oct. 23 parser existed; their game date does not date the write. It is plausible that a historical backfill or later refresh ran the fallback, but no Dec. 14 command log, database statement log, or row-level source receipt is retained, so the exact writer is unproven. The 23 rows are not all attributable to the Oct. 6 SOG-only parser: some stored values exceed SOG and equal the three-term fallback signature.

The pre-live dump comparison also proves the table did not remain immutable after the dump. It does not say whether all earlier-season values were originally correct, nor whether the later changes were all defects. In particular, the large attempt and PP-TOI deltas require official-source validation before deciding which should be restored. The operator's original-pristine premise is consistent with the dump's timing, but full source provenance is not available to verify it independently.

## Minimum prevention boundary

The smallest reliable separation is a database permission boundary, not an application convention:

- Keep canonical official source observations append-only with request time, endpoint, response hash, source player/game identity, and validation result.
- Give normal official ingestion a narrowly scoped database role that may append validated observations and perform the required keyed promotion.
- Give research, model development, scoring, and evaluation read-only roles on the canonical source table. Route derived values to separate feature/staging tables.
- Make any historical correction a separately authorized, key-bounded operation with retained before/after rows and provenance.

The repository currently uses the same database URL in ingestion and analysis entry points; no role separation is demonstrated here. A trigger or code allowlist alone would not prevent another privileged client from rewriting the table.

## Current status and remaining evidence gaps

The read-only official-PBP recovery now covers all 1,306 game IDs and all 46,713 rows in the current 2025-prefix snapshot. It used the existing `official_get` request journal and `derive_attempts_from_final_pbp` validator. It captured 1,300 new official PBP responses (all HTTP 200, one network attempt each) and reused six previously retained, hash-bound sample responses. Raw source payloads, request journal, and response ledger are retained under `artifacts/analysis/nhl/points_attempts_2025_full_recovery_2026-10-16/official_pbp/`.

The game-by-game validator accepted 1,128 games and rejected 178: 146 failed exact player SOG reconciliation and 32 had shooter identity failures. Rejected games are unresolved; their rows were not assigned counts or zeros. The 46,713-row candidate classifies 6,237 stored values as matching validated PBP, 20,072 as differing from validated PBP, 14,036 NULL rows as recoverable from validated PBP, 12 rows as identity unresolved, and 6,356 rows as unresolved because their games failed validation. Of the 20,072 validated discrepancies, 1,633 are stored zero vs positive official count, 14,847 are positive stored counts below official, and 3,592 are positive stored counts above official; 766 of those positive-over cases have official count zero. The old boxscore fallback signature matches 17,162 discrepant records; the remaining 2,910 are discrepancies of another shape. These are source comparisons and correction candidates only; no SQL update was run.

Earliest demonstrable departure from complete source validation in the retained implementation history is the Sep. 27 direct PBP-to-raw importer, which computed attempt fields without final-state and player-SOG reconciliation. The Oct. 10 snapshot is the earliest trustworthy *state checkpoint*, not a source-validated checkpoint. No later full-database backup or raw write audit was found.

No database, model, authority, prediction, or production scoring change was made during this investigation. The 2025 candidate is prepared but not applied; rejected games and identity cases remain unresolved. Source validation of older seasons and non-attempt fields remains necessary before claiming the full original foundation can be reconstructed. The Points foundation investigation remains open.
